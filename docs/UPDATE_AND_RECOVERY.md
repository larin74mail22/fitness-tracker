# Обновление и восстановление FITNESS Tracker

## Обновление кода

1. Остановить трекер: значок → «Выход» (или `python tracker.py --stop`).
2. Заменить файлы проекта (git pull или копирование). Папку `data\` не трогать: там база, настройки и журналы.
3. Если в обновлении есть новая миграция (`fitness\migrations\00N_*.sql`), трекер и MCP сообщат «схема базы
   устарела». Обновление схемы — отдельной командой, она сама делает и проверяет резервную копию:
   `python migrate_db.py` (при остановленном трекере).
4. Запустить `tracker.pyw`. Туннель запускается заново, поэтому ChatGPT получает новую версию `server.py`.
   Если появились новые инструменты — обновить приложение/коннектор в настройках ChatGPT.
5. Проверка: `python tracker.py --status` (или «Состояние…»), строка «Проверка MCP … server.py отвечает».

EXE-сборка (если используется): после обновления кода пересобрать `scripts\build_exe.ps1`. Сборка не содержит
базы и настроек, поэтому замена `dist\FitnessTracker` данные не затрагивает. Автозапуск переключается между EXE и
`pythonw` повторным запуском `scripts\install_autostart.ps1`.

## Сбои и что происходит с данными

| Ситуация | Что будет |
|---|---|
| Выключение/перезагрузка Windows | трекер получает уведомление о завершении сеанса и останавливает импорт и туннель по порядку |
| Аварийное завершение трекера | tunnel-client и server.py завершаются вместе с ним (Job Object); блокировка снимается системой, следующий запуск проходит обычно |
| Обрыв посреди импорта файла | транзакция SQLite откатывается целиком; файл остаётся в `health_inbox` и импортируется при следующей проверке |
| Обрыв между записью в базу и переносом файла | при следующей проверке файл узнаётся по SHA-256 («уже был в базе») и переносится в `health_processed` |
| Падение tunnel-client | перезапуск через 5 с, 10 с, … до 5 мин; причина и последние строки вывода — в `data\logs\tracker.log` |
| server.py не отвечает | «Проверка MCP» (при запуске, раз в час и по пункту меню) пишет ошибку в журнал и показывает уведомление |

## Восстановление базы из резервной копии

Копии лежат в `data\backups\fitness-ДАТА-ВРЕМЯ*.db` (создаются перед удалением записей, перед миграцией и по
инструменту `backup_database`).

1. Остановить трекер (`python tracker.py --stop`) и закрыть `dashboard.bat`, если он открыт.
2. Переименовать текущие `data\fitness.db`, `data\fitness.db-wal`, `data\fitness.db-shm` (не удалять), например
   в `fitness.db.broken`.
3. Скопировать выбранную копию в `data\fitness.db`.
4. Запустить трекер и проверить «Состояние…» → «Проверка MCP: база в порядке».

Данные Health Connect за период после копии можно вернуть повторным импортом файлов из `data\health_processed`:
скопировать нужные файлы в `data\health_inbox` — уже имеющиеся в базе записи дубликатов не создадут.

## Сброс состояния трекера

- `data\launcher.json` можно удалить — при запуске создастся заново со значениями по умолчанию;
- `data\run\` — служебные файлы работающего экземпляра; удалять не нужно (устаревшие файлы не мешают запуску);
- `data\logs\` — журналы можно удалять при остановленном трекере.
