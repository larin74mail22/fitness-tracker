# Импорт выгрузки Health Connect через ChatGPT (MCP)

Сценарий: пользователь прикрепляет JSON из приложения FITNESS Health Export к сообщению в ChatGPT, ChatGPT вызывает
`import_health_export`, локальный сервер проверяет файл и записывает его в `data\fitness.db` тем же импортёром, что и
`import_health.py` (`health_import.import_bytes`). PowerShell и копирование файла в папку проекта не нужны.

## Почему не «содержимое JSON в аргументе»

Аргументы вызова инструмента ChatGPT пишет сам, токен за токеном. Файл за 30 дней может весить около 10 МБ
(десятки тысяч записей пульса), даже сжатый в base64 это больше миллиона токенов. Поэтому основной путь — **параметр файла**
Apps SDK: инструмент объявляет `_meta: {"openai/fileParams": ["file"]}`, и ChatGPT вместо содержимого передаёт объект
`{download_url, file_id, mime_type, file_name}` с временной ссылкой на прикреплённый файл. Сервер скачивает файл сам.

## Инструменты

| Инструмент | Назначение |
|---|---|
| `import_health_export` | Импорт. Ровно одно из: `file` (файл из сообщения) или `upload_id` (передача частями). Флаги `dry_run`, `allow_gaps`, `allow_older` — как у `import_health.py`. |
| `start_health_upload` | Запасной путь, только для небольших файлов: объявить размер, SHA-256 и число частей (`encoding`: `utf8` или `base64`). |
| `upload_health_chunk` | Передать часть `index` (от 0). Порядок любой, повтор той же части безопасен, другая часть под тем же номером — ошибка. |
| `get_health_imports` | Журнал импортов (успешные и неудачные, счётчики, ошибки) и последний принятый номер файла по телефонам. Только чтение. |

Результат импорта: `status` (`imported`, `already_imported`, `dry_run`), `import_id` (строка журнала), `phone_id`,
`sequence`, `exported_at`, `data_range` (самое раннее начало и самый поздний конец записей в UTC, местные даты),
`counts` по типам (`inserted`, `updated`, `unchanged`, `deleted`, `rejected`), `totals`, `skipped` (не применено:
устаревшие версии, повтор удалённого, конфликты, чужие и устаревшие удаления), `unmatched_deletions`, `warnings`.
Ошибка: `ok: false`, `error` (`import_file_invalid`, `import_order`, `transfer_failed`, `database_missing`, …),
`message`, для неверного файла `problems` с местами в файле, `hint`.

## Безопасность

- Путей к файлам на диске инструмент не принимает. Произвольных команд, SQL и файлов нет.
- Ссылка: только `https`, стандартный порт, без логина в адресе, не IP-адрес; имя должно указывать только на
  публичные адреса (не localhost и не локальная сеть). Каждый редирект проверяется так же. Не больше 50 МБ, таймаут
  60 с. Ограничение: проверка адреса и само соединение — два отдельных разрешения имени (теоретически возможна подмена
  DNS между ними); для локального личного сервера это принято.
- Части передачи лежат в `data\health_uploads\<id>\` (папка `data` не попадает в git), удаляются после успешного
  импорта и автоматически через 24 часа. `upload_id` — 32 символа `0-9a-f`, другого пути к файлам нет.
- Незавершённая передача (нет части), неверный размер или SHA-256 — импорт не запускается.
- База не создаётся и не мигрирует: без базы последней версии схемы импорт и передача отказывают.

## Идемпотентность, порядок, параллельные вызовы

Правила импортёра не менялись (docs/HEALTH_EXPORT_FORMAT.md): записи сопоставляются по паре «источник, `hc_id`»
(стабильный id записи Health Connect), повторный файл узнаётся по SHA-256, перекрывающиеся периоды дают `unchanged`,
изменения применяются только с более новым `last_modified`, файл пишется одной транзакцией `BEGIN IMMEDIATE`. Два
одновременных импорта выполняются по очереди (блокировка записи SQLite, ожидание до 10 с); второй экземпляр того же
файла получает `already_imported`. Сон хранится одной сессией с исходными интервалами UTC и стадиями, местная дата сессии —
дата пробуждения; полночь сессию не разбивает.

Номер файла (`sequence`) растёт на телефоне при каждом экспорте, даже если файл не отправили в чат. Тогда следующий
импорт получит `import_order` (пропуск номера). Благодаря нахлёсту периодов пропущенный файл обычно не нужен: ChatGPT
объясняет это пользователю и с его согласия повторяет вызов с `allow_gaps=true`.

## Как подключить

Новый инструмент появится в ChatGPT после перезапуска процесса `server.py`: перезапустите tunnel-client (профиль
`fitness-local`) тем же способом, каким он запускается обычно, и при необходимости обновите приложение в настройках
ChatGPT, чтобы оно перечитало список инструментов. Конфигурация туннеля не меняется.

## Чтение данных и автоматический импорт (этап 8)

| Инструмент | Назначение |
|---|---|
| `get_daily_activity` | **Суточные итоги для расчёта активности и калорий**: каждый день периода (`date_from`, `date_to`, до 93 дней) отдельной строкой — `steps`, `sleep`, `heart_rate`. Нет данных — `null` (не 0) и причина в `*_status`: `ok`, `no_records`, `not_imported_yet`, `before_first_record`. Только чтение. |
| `get_health_summary` | Шаги, пульс, сон за период (`date_from`/`date_to` или `days` по сегодняшнюю местную дату компьютера), по дням и итогом, сравнение с предыдущим периодом той же длины. Только чтение. |
| `get_health_sync_status` | Последний успешный импорт, число импортированных файлов и неудачных попыток, свежесть данных по типам, очередь входящей папки, список `attention`. Только чтение. |
| `import_health_inbox` | Импортировать файлы, уже лежащие в `data\health_inbox` (тот же импортёр). Путей не принимает. |

Числа считаются по базе (`fitness/health_status.py`, те же правила, что у панели). Пропуск номеров, перекрытый
периодом файла, принимается сам (поле `gap` в ответе), см. `docs/HEALTH_AUTO_IMPORT.md`.

### Шаги по дням (`get_daily_activity`)

Шаги в базе хранятся интервалами (`step_intervals`, обычно по 10 минут), а не дневными итогами. Итог дня — сумма
интервалов за местную дату `local_date` (по началу интервала и часовому поясу самой записи). Перекрывающиеся
интервалы одного источника не считаются дважды, при нескольких источниках берётся наибольший (те же правила, что у
панели, `fitness/web/health.py`). Сон относится к дате пробуждения.

Пример строки ответа (числа выдуманные):

```json
{"date": "2026-01-15", "steps": 8000, "steps_status": "ok",
 "sleep": {"in_bed_min": 480.0, "asleep_min": 460.0, "deep_min": 80.0, "light_min": 280.0, "rem_min": 100.0,
           "awake_min": 20.0, "sessions": 1}, "sleep_status": "ok",
 "heart_rate": {"min_bpm": 55, "avg_bpm": 70.0, "max_bpm": 120, "samples": 900}, "heart_rate_status": "ok"}
```

После добавления инструмента ChatGPT увидит его только после перезапуска сервера (tracker.pyw или туннель) и
обновления приложения в настройках ChatGPT: список инструментов ChatGPT запоминает при подключении.
