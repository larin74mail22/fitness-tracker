# Автоматический импорт Health Connect на компьютере

Путь данных: часы → Zepp → Health Connect → приложение **FITNESS Health Export** (JSON) → папка синхронизации на
телефоне → Syncthing → `data\health_syncthing` на компьютере → копия в `data\health_inbox` → `health_inbox.py` →
база `data\fitness.db` → MCP (ChatGPT) и панель. Передача с телефона описана в `docs/HEALTH_PHONE_TRANSFER.md`,
настройка Syncthing без «Отменить локальные изменения» — в `docs/HEALTH_SYNCTHING.md`.

## Папки

| Папка | Что там |
|---|---|
| `data\health_syncthing` | папка Syncthing «Только приём»; импорт её только читает и копирует новые готовые файлы в `health_inbox` |
| `data\health_inbox` | новые файлы `*.json`: копии из `health_syncthing`, файлы от adb или положенные вручную |
| `data\health_processed` | файлы, которые уже есть в базе (импортированы сейчас или раньше) |
| `data\health_failed` | файлы, не прошедшие проверку; рядом `<имя>.error.txt` с причиной |
| `data\health_sync` | `last_run.json` (последний запуск с файлами), `runs.log` (журнал запусков), `last_check.json`, `syncthing_handoff.json` (какие файлы Syncthing уже переданы) |

Папки создаются при первом запуске импорта (`health_syncthing` создаёт сам Syncthing). Папка `data` не попадает в
git. Файлы никогда не удаляются.

## Запуск

Двойной щелчок по файлам в папке проекта:

| Файл | Что делает |
|---|---|
| `health_import_inbox.bat` | один раз обрабатывает все новые файлы и показывает результат |
| `health_import_inbox.bat --watch` | наблюдает за папкой (проверка раз в 30 с), пока окно открыто |
| `health_status.bat` | состояние синхронизации: последний импорт, свежесть данных, очередь, ошибки |
| `dashboard.bat` | панель http://127.0.0.1:8765/, раздел «Синхронизация» |

Из командной строки то же: `python health_inbox.py [--watch | --status |
--retry-failed | --dry-run] [--allow-gaps] [--allow-older] [--json]`. Через ChatGPT: инструмент `import_health_inbox`.

Коды выхода: `0` всё обработано, `1` ошибки файлов или базы, `2` есть ожидающие файлы, `3` папку уже обрабатывает
другое окно.

## Что происходит с каждым файлом

0. **Передача из папки Syncthing.** Новый файл `data\health_syncthing` копируется в `health_inbox`, когда он
   дописан (не меняется размер и время, создан не меньше 5 секунд назад, JSON не обрезан). Копия пишется под
   временным именем и проверяется по SHA-256. Каждое содержимое передаётся один раз; уже импортированное в базу не
   копируется. Сама папка Syncthing не меняется. Подробнее — `docs/HEALTH_SYNCTHING.md`.
1. **Готовность.** Временные имена (`.*`, `~*`, `*.tmp`, `*.part`, `*.crdownload`, …) и подпапки пропускаются. Файл,
   изменённый меньше 5 секунд назад, изменивший размер за секунду проверки или занятый другим процессом, считается
   копирующимся («busy») и ждёт следующего запуска. Недописанный JSON моложе минуты тоже ждёт, а не идёт в ошибки.
2. **Порядок.** Файлы обрабатываются по телефону и номеру файла, а не по имени.
3. **Импорт** тем же импортёром, что у `import_health.py` и MCP (`docs/HEALTH_EXPORT_FORMAT.md`): проверка файла
   целиком, одна транзакция, повтор файла узнаётся по SHA-256, пересекающиеся периоды не дублируются.
4. **Итог:**
   - `imported` или `already_imported` → файл переносится в `health_processed` (при совпадении имени добавляется
     метка времени);
   - неверный файл, неподдерживаемая версия, номер уже занят другим содержимым → `health_failed` + `.error.txt`;
   - пропуск номеров, который нельзя принять без потери периода, или файл старше принятого → остаётся во входящей
     папке («held»), причина видна в отчёте, `health_status.bat` и на странице «Синхронизация»;
   - нет базы, нужна миграция, база занята → запуск останавливается, все файлы остаются во входящей папке.
5. **Сбой посередине** (выключили компьютер после импорта, но до переноса) безопасен: при следующем запуске файл
   узнаётся как `already_imported` и переносится.

## Пропуск номеров и потеря периода

Номер файла растёт на телефоне при каждом созданном файле, а «С последнего экспорта» на телефоне считается от
последнего **созданного** файла, не импортированного. Если файл №N не дошёл до компьютера, следующий файл может не
содержать часть его периода. Защита в импортёре:

- приложение 0.3+ пишет в файл период чтения `period_start`/`period_end`;
- при пропуске номеров импортёр сравнивает начало периода нового файла с концом последней записи этого телефона в
  базе (`covered_until`); если файл начинается не позже — промежуток перекрыт, файл принимается сам с
  предупреждением (`gap.accepted = "covered"`);
- иначе файл не принимается, и сообщение называет непокрытый промежуток: найдите пропущенный файл или сделайте на
  телефоне экспорт «Последние 30 дней» (или произвольный период от названной даты). Принять файл с потерей можно
  только явно: `--allow-gaps`;
- файлы старых версий без периода, как и раньше, требуют `--allow-gaps`.

Пропущенный файл, нашедшийся позже (номер меньше принятого), импортируется ключом `--allow-older`: более новые данные
он не откатывает.

## Первый запуск

1. `health_status.bat` — убедиться, что база доступна.
2. Положить файл выгрузки в `data\health_inbox` (или настроить синхронизацию) и запустить
   `health_import_inbox.bat`.
3. Открыть `dashboard.bat` → «Синхронизация»: последний импорт, свежесть данных, очередь.

## Автозапуск после входа в Windows (необязательно)

С версии 1.0 наблюдение за папками входит в единый запуск трекера (`tracker.pyw`, см. `QUICKSTART.md`), отдельное
окно `health_import_inbox.bat --watch` не нужно. `scripts\install_autostart.ps1` создаёт задачу Планировщика
«FITNESS Tracker», которая запускает трекер без окон после входа; `-Remove` — выключить. Старый ярлык автозапуска
окна наблюдения скрипт удаляет. Сам по себе скрипт не запускается.

## Типичные ошибки

| Что видно | Что делать |
|---|---|
| «База данных не найдена» / «Схема базы устарела» | базу не создаёт и не обновляет импорт; обновление схемы — `migrate_db.py` при остановленном туннеле |
| «database is locked» | база занята долгой операцией; файлы остались, запустите импорт ещё раз |
| файл в `health_failed`, «это не JSON» | файл повреждён или обрезан при передаче: экспортируйте заново на телефоне |
| «поддерживается только версия формата 1» | приложение на телефоне новее трекера: обновите трекер |
| «неизвестные поля верхнего уровня: period_start…» | трекер старше приложения 0.3: обновите трекер |
| файл «ожидает», пропущены файлы | см. «Пропуск номеров» выше |
| «уже обрабатывает другое окно» | закройте второе окно с `--watch` |
| исправили причину ошибки | `health_import_inbox.bat --retry-failed` вернёт файлы из `health_failed` и обработает их |
| время в отчётах на 3 часа отличается | время импорта и экспорта — UTC; даты записей — местные по поясу телефона |
