# Syncthing без «Отменить локальные изменения»

## Почему появлялась красная кнопка

Папка Syncthing на компьютере имеет тип **«Только приём»** (Receive Only). Syncthing считает её копией папки
телефона, и любое изменение на компьютере — удаление, перенос, переименование, новый файл — для него «локальное
изменение». Раньше Syncthing принимал файлы прямо в `data\health_inbox`, а импортёр переносил их оттуда в
`health_processed`. Для Syncthing это выглядело как удаление файлов, отсюда «Отменить локальные изменения». Нажатие
кнопки возвращало файлы обратно, и импорт переносил их ещё раз (в `health_processed` появлялись копии с меткой
времени, например `…__20261012T231029.json`).

## Как устроено теперь

```
телефон (Только отправка)
   └─ Syncthing ─► data\health_syncthing     (Только приём; импорт её ТОЛЬКО ЧИТАЕТ)
                       │  копия готового файла (health_handoff.py)
                       ▼
                  data\health_inbox  ─► импорт ─► база
                                         ├─► data\health_processed
                                         └─► data\health_failed (+ .error.txt)
```

- Импорт (`health_import_inbox.bat`, `--watch`, автозапуск, инструмент `import_health_inbox` в ChatGPT) перед
  обработкой входящей папки копирует новые готовые файлы из `data\health_syncthing` в `data\health_inbox`.
- В `data\health_syncthing` ничего не создаётся, не меняется и не удаляется, поэтому у Syncthing нет локальных
  изменений и красной кнопки.
- Каждый файл передаётся один раз: SHA-256 переданных файлов хранится в `data\health_sync\syncthing_handoff.json`.
  Файл, который уже есть в базе, не копируется вовсе.
- Недописанный файл (свежий, меняется размер, обрезанный JSON моложе минуты) ждёт следующей проверки.
- Файлы в `data\health_syncthing` остаются как есть: это и есть исходники до и после импорта. Чистить их можно на
  телефоне (тогда Syncthing уберёт их и на компьютере) или не чистить вовсе.

## Что сделать в Syncthing (один раз)

Телефон и Syncthing-Fork трогать не нужно: папка на телефоне остаётся **«Только отправка»**, устройства остаются
сопряжёнными. Меняется только путь папки на компьютере. Путь существующей папки Syncthing не даёт поменять, поэтому
папку на компьютере убирают и сразу добавляют снова с тем же ID.

1. Закрыть окно наблюдения (`health_import_inbox.bat --watch`), если оно открыто.
2. Открыть http://127.0.0.1:8384/. В списке папок раскрыть папку телефона (путь
   `<папка проекта>\data\health_inbox`) → «Изменить». На вкладке «Общие» **переписать ID папки**
   (вида `abcde-12345`) и метку. Кнопку «Отменить локальные изменения» не нажимать.
3. В том же окне нажать «Удалить» (Remove) и подтвердить. Удаляется только настройка в Syncthing; файлы на диске
   остаются.
4. «+ Добавить папку»:
   - «Общие»: метка — та же; **ID папки — точно тот же**, что в шаге 2; путь —
     `<папка проекта>\data\health_syncthing`;
   - «Предоставить доступ»: отметить телефон;
   - «Дополнительно»: тип папки **«Только приём»** (Receive Only);
   - «Сохранить».

   Если вместо этого сверху появилось «Телефон хочет поделиться папкой …» — можно нажать «Добавить» там же и
   заполнить те же поля.
5. По желанию: Действия → Дополнительно → Папки → эта папка → включить «Ignore Delete». Тогда чистка папки на
   телефоне не удалит файлы на компьютере. Для импорта это не обязательно.
6. Подождать, пока папка станет «Актуально». Syncthing скачает в `data\health_syncthing` все файлы, которые сейчас
   лежат на телефоне. Уже импортированные импорт узнает по SHA-256 и не тронет; в базу ничего не добавится повторно.
7. Запустить `health_import_inbox.bat` (один раз) или `--watch` (или войти в Windows заново, если стоит автозапуск).

Уже существующие файлы: `data\health_processed` и `data\health_failed` не меняются. `data\health_inbox` остаётся
обычной входящей папкой (adb, ручное копирование). В ней осталась пустая служебная папка Syncthing `.stfolder` —
она ни на что не влияет, после перенастройки её можно удалить вручную. Пока в `health_inbox` есть `.stfolder`, а в
`health_syncthing` её нет, `health_status.bat` напоминает о перенастройке.

## Проверка

1. На телефоне: FITNESS Health Export → «Экспортировать данные».
2. В Syncthing на компьютере: папка «Актуально», в `data\health_syncthing` появился новый `fitness-health-….json`.
3. Окно `--watch` (проверка раз в 30 с) пишет `Syncthing → входящая: fitness-health-….json`, затем
   `…: импортирован (файл №N, …)`.
4. `health_status.bat`: «Папка Syncthing: … ещё не передано на импорт 0», «Последний успешный импорт» с новым
   номером, «Всё в порядке».
5. В Syncthing у папки **нет** «Локальные изменения» и красной кнопки, ни сразу, ни после следующих экспортов.

## Восстановление после сбоя

| Что случилось | Что будет |
|---|---|
| компьютер выключили во время передачи Syncthing | Syncthing докачает файл после включения; недописанный файл не копируется |
| выключили между копированием и записью журнала | копия во входящей папке узнаётся по SHA-256, вторая не создаётся |
| выключили после импорта, до переноса | файл узнаётся как `already_imported` и переносится в `health_processed` |
| ошибка копирования (диск, права) | видна в отчёте и `data\health_sync\runs.log`, код выхода 1; повтор при следующей проверке |
| журнал `syncthing_handoff.json` удалён или повреждён | повреждённый сохраняется рядом (`.corrupt-…`); уже импортированные файлы узнаются по базе |
| файл с ошибкой | копия в `health_failed` + `.error.txt`, исходник остаётся в `health_syncthing`; после исправления — `--retry-failed` |

Кнопку «Отменить локальные изменения» нажимать не нужно ни в одном из этих случаев. Если она всё-таки появилась у
папки `health_syncthing`, значит кто-то изменил файлы в ней вручную: верните их (или нажмите кнопку — импорт
повторы отсеет) и больше не меняйте эту папку.
